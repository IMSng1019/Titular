# Titular 称号模组设计

## 目标

为 Fabric 1.20.4、Yarn 和 Java 17 实现服务端权威的纯视觉称号系统。称号只装饰玩家在聊天、头顶名称和 Tab 列表中的显示文本，不修改玩家档案名、命令匹配名或签名聊天正文。

## 架构

系统分为共享领域层、服务端适配层和客户端表现层。

- `model` 保存称号、组、玩家状态、设置和权限等级等不可变数据。
- `storage` 通过 `TitularStorage` 隔离持久化，首版提供 `JsonTitularStorage`。
- `service` 是唯一业务写入口，负责继承解析、可用称号计算、权限校验、修改、持久化和修订号递增。
- `network` 使用 Fabric 1.20.4 的 Identifier/PacketByteBuf 通道同步权限裁剪后的快照，并接收命令式 C2S 请求。
- `client` 保存只读镜像，提供选择与管理界面，并在头顶名称和 Tab 列表渲染点调用共享格式化器。

所有 C2S 请求都携带客户端已知修订号。服务端始终重新检查权限和当前状态；过期请求返回错误并重发最新快照。

## 数据模型

### 称号

`TitleDefinition` 包含稳定 ID、前缀 `Text` 和后缀 `Text`。配置 codec 使用受限的 literal styled-run JSON（`text`、颜色、粗体、斜体、下划线、删除线和 `extra`）；这正好覆盖编辑器能力，并拒绝点击/悬停/翻译等注册表相关组件，避免配置加载依赖 Minecraft bootstrap。空片段合法。

### 组

`GroupDefinition` 包含稳定 ID、可空的单个 `parent` 和有序称号 ID 列表。组 ID 同时作为 LuckPerms 组名匹配键。

### 玩家

`PlayerTitleState` 包含：

- `primaryGroup`
- `extraGroups`
- `extraTitles`
- `activeTitle`
- 内部 `luckPermsGroups` 镜像

`luckPermsGroups` 单独记录由 LuckPerms 同步的组，避免权限组变化覆盖人工设置的 `primaryGroup` 或 `extraGroups`。它作为向后兼容的可选 JSON 字段保存；旧文件缺失时按空集合处理。有效组池由主组、额外组和 LuckPerms 镜像组共同组成。

### 设置

`TitularSettings` 首版只包含 `DisplayMode`：`PREFIX`、`SUFFIX` 或 `BOTH`，默认 `PREFIX`。网络修订号是进程内并发令牌，不写入配置，服务器重启后从 0 开始。

## 权限

权限分为三级，服务端统一计算：

- `PLAYER`：选择自己继承池中的 `activeTitle`。
- `ADMIN`：OP 等级至少 2 或拥有 `titular.admin`，并可修改自己的 `primaryGroup`。
- `SUPERADMIN`：OP 等级至少 4 或拥有 `titular.superadmin`，继承全部能力，并可管理组、继承关系、称号定义、全局设置，以及任意在线或离线玩家的 `primaryGroup`、`extraGroups` 和 `extraTitles`。

客户端只依据服务端下发的能力标记显示入口；隐藏按钮不构成安全边界。

## 继承与可用称号

解析每个起始组时沿单一 `parent` 链向上遍历，并为每条链维护访问集合。遇到循环、缺失组或缺失称号时记录 warning，跳过无效引用并继续处理其他来源。

合并顺序为：

1. `primaryGroup` 及其父链
2. `extraGroups` 及各自父链
3. `luckPermsGroups` 及各自父链
4. `extraTitles`

使用保持插入顺序的集合去重。激活请求只接受当前可用池中的称号 ID；无可用称号或原激活称号失效时，显示为空，但不自动选择其他称号。

删除组时拒绝仍被其他组作为父组引用的操作，除非请求同时明确清除引用。删除称号时从所有组和玩家额外称号中清理该 ID，并清空受影响玩家的 `activeTitle`。

## 存储

配置位于 `config/titular/`：

- `titles.json`
- `groups.json`
- `players.json`
- `settings.json`

首次启动生成语义为空的四个文件，不创建示例数据。JSON 由显式 codec 读写，不直接反射序列化 Minecraft 类型。

每次保存先写同目录临时文件，再以替换方式移动到目标路径，避免半写文件。加载失败时：

- 已有内存快照时保留旧快照并拒绝用空数据覆盖损坏文件。
- 首次启动遇到损坏文件时，将文件重命名为带时间戳的 `.broken-*` 备份，再为该部分加载空默认值并记录 error。
- 业务校验失败不写盘。

`save` 接收完整不可变 `TitularData`，因此未来 MySQL 实现可维持相同服务接口。

## 网络与快照

服务端为每个接收者生成权限裁剪后的 `ClientSnapshot`：

- 所有人：修订号、显示模式、在线玩家的激活称号显示数据、自己的状态和可用称号。
- `ADMIN`：额外获得所有有效组 ID，用于修改自己的主组。
- `SUPERADMIN`：额外获得全部组、称号和已保存玩家状态，以及离线玩家的可解析名称。

C2S 请求使用明确操作类型，不允许客户端回传整个配置覆盖服务端：

- 激活/清除自己的称号
- 管理员修改自己的主组
- 高级管理员创建、更新、删除组
- 高级管理员创建、更新、删除称号
- 高级管理员修改任意玩家的主组、额外组和额外称号
- 高级管理员修改显示模式
- 请求重载和刷新快照

成功修改的顺序固定为：校验、生成新数据、原子保存、替换内存状态、修订号递增、向在线玩家广播各自的新快照。失败时发送本地化错误消息，不改变内存或磁盘。

## LuckPerms 软依赖

构建时使用 `compileOnly` LuckPerms API，运行时先通过 `FabricLoader.isModLoaded("luckperms")` 检查，再加载独立集成类，保证缺少 LuckPerms 时不会解析其 API 类型。

权限节点通过 LuckPerms cached permission data 查询。组同步把用户继承到且在 Titular 中存在同名定义的 LuckPerms 组写入 `luckPermsGroups`。监听用户数据重算事件，比较新旧集合，只持久化发生变化的玩家；人工主组和额外组保持不变。LuckPerms 缺失时完全忽略镜像字段的更新，继续使用 JSON 状态。

## 统一格式化与渲染

`TitularFormatter` 输入原始玩家名 `Text`、可空激活称号和显示模式，返回新的 `Text`。原始名字作为独立 sibling 复制，内容和样式不变；称号前后片段也分别复制，避免样式向名字泄漏。

- 聊天：在服务端聊天装饰链中替换消息类型参数里的显示名，不改签名正文。
- 头顶名称：客户端 mixin 在玩家实体名称返回点格式化。
- Tab：客户端 mixin 在玩家列表条目名称返回点格式化。

三处都使用相同的 `TitularFormatter` 测试夹具。客户端渲染只读取一个原子替换的快照引用，避免界面、Tab 和头顶名看到不同版本。

## 客户端界面

`/titular` 由服务端发送打开界面包，避免纯客户端命令绕过权限上下文。

- 玩家页：显示可用称号、当前选择和格式化预览。
- 管理员页：增加自己的主组选择器。
- 高级管理员页：增加玩家、组、称号和设置标签页。

富文本编辑器内部使用纯文本加逐字符样式文档。鼠标拖动产生半开区间选择；颜色、粗体、斜体、下划线、删除线和重置操作只修改选区样式。相邻相同样式在转换为 `Text` 时合并为 run。编辑器永远渲染实际视觉效果，不展示 `§` 或 JSON 格式代码。

离线玩家管理使用已保存 UUID 列表和服务器用户缓存解析名称；名称无法解析时显示 UUID，仍可编辑。

## 测试

纯领域测试覆盖继承、多源合并、循环、缺失引用、去重、激活校验、三级权限和 LuckPerms 组差异合并。格式化测试比较完整 Text 树，确认名字内容与样式不变。存储测试使用临时目录验证首次生成、往返、原子覆盖和损坏文件备份。

网络处理器通过注入的权限与服务接口测试普通玩家伪造管理请求、过期修订号和成功修改后的广播。富文本编辑文档测试选区、插入删除和样式 run 合并。Mixin 只做薄适配，使用编译、开发客户端和开发服务端烟雾测试验证。

## 环境限制

当前工作目录不包含 Git 元数据，因此无法创建 worktree、提交设计文档或按任务提交代码。实施仍在当前目录按测试先行完成，最终通过 `gradlew test`、`gradlew build` 和开发运行验证。
